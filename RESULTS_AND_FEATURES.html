2. DSP stages

  1. Resampling: native 44.1 kHz input is converted to the configured processing rate of 8 kHz.
  2. AGC: normalizes level while refusing to amplify extremely quiet input.
  3. Spectral subtraction: estimates ambient noise from the quiet lead-in and reduces it.
  4. Hybrid endpoint detection: combines short-time energy and zero-crossing behavior to locate speech.
  5. Low-frequency liveness: checks sub-200 Hz energy as a replay/loudspeaker signal-quality guard.
  6. Feature front-end: configured MFCC or DFT sequence.
  7. DTW: compares variable-rate speech sequences to enrolled templates.

5. Coupon registry

MonthlyCouponRegistry.csv is administered privately. Each row binds one unique coupon to one student and one yyyy-MM month. Consumption records a used flag and timestamp; reuse, wrong student, and wrong month are rejected.

6. Security boundary

  • Public users see Verify Meal only; identity dropdowns and demo selectors are not presented.
  • Admin uses ID admin and password admin by default in this demonstration build.
  • Meal log, monthly payment records, corpus audit, enrollment, signal graphs, DSP Explorer, result tables, and evaluations are admin-only.
  • Admin Lock clears the private table and removes private workspace tabs.
  • File-system access must also be restricted in a real deployment; GUI hiding alone is not an operating-system security boundary.

7. Reproducibility notes

The regression redirects both meal and monthly-entitlement files to temporary paths and deletes them afterward. This prevents test traffic from changing production records. The active v2 copy is backed up under Backups; use backup_project.ps1 from the project root before future edits.

8. Limitations and responsible use

  • The system performs speaker recognition, not speech transcription. It does not independently know whether the spoken audio content literally spells the displayed ID.
  • Default admin/admin credentials are suitable only for demonstration; change them before deployment.
  • Biometric voice data requires institutional privacy approval, access control, retention rules, and user notice.
  • Microphone quality, room noise, channel mismatch, and replay conditions can affect accuracy; use the microphone test and quality diagnostics.
